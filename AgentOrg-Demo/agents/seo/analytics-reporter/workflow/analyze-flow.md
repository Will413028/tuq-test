# Analytics Reporter — Analyze Flow (Plan/Analyze)

R-D-V 第二段：對輸入包做排名/流量分析、KPI 對齊、歸因與 A/B 觀察。由 workflow.yaml `analyze` 步驟 route 到此。

## 流程步驟

### 1. 排名追蹤分析
- 比對目標關鍵字當期 vs 基準期排名。
- 標出進入/跌出前三名、前十名的關鍵字。
- 區分短期波動 vs 結構性變化（連續多期趨勢）。

### 2. 自然流量分析（GSC + GA4）
- GSC：曝光、點擊、CTR、平均排名趨勢。
- GA4：自然流量 session、engagement、轉換趨勢。
- **跨來源指標標記為不可直接相比**（GA4 session ≠ GSC click）。

### 3. 待算清單彙整 → 委派 shared/calculator
所有精確數值不自行心算，彙整為待算清單交 Manager 派 calculator：
| 指標 | 原始數值 | 公式 |
|------|---------|------|
| 自然流量成長率 | 當期 session / 基準期 session | (當期−基準)/基準 ×100% |
| CTR 變化 | 點擊 / 曝光 | 當期 CTR − 基準 CTR |
| KPI 達成率 | 當期值 / 半年目標值 | 當期/目標 ×100% |
- 未經 calculator 驗證的數字一律標「待驗證」。

### 4. KPI 對齊
- 將每項指標回扣半年成長目標：目前達成度 vs 目標。
- 依現有趨勢推估達成路徑，標出落後/超前。

### 5. 成效歸因（保守）
- 對照時間線事件（內容上線、技術修正、演算法更新、季節性）解釋變化。
- 每條歸因標證據強度：**已證實**（數據+時間線佐證）/ **相關但未證實**（列出需補的驗證資料）。

### 6. A/B / 前後觀察（如適用）
- 對照變更前後成效，列出同期其他變動。
- 結論分級：變因隔離良好 → 可下「有效/無效」；否則僅報告觀察值。

## 輸出
- 分析結果結構：排名變化 + 流量趨勢 + KPI 達成度 + 歸因表 + A/B 觀察 + 待驗證數字清單。
- 交給 report-flow。

## 注意事項
- 寧可標「不確定」也不編因果故事。
- 任何結論都要能溯源到第 1–2 步的標來源數據。
